## 1. Why monetise the protocol at all

CRP is the wire format that lets `crp-comply` (and any future product
built on the protocol) provide deterministic, auditable, multi-LLM
context relay. The protocol itself is currently MIT-permissive, which is
correct for adoption but leaves zero capture of the value generated by
**enterprises** running CRP in production. The plan below introduces
**five revenue streams stacked on top of an open core** without
breaking the OSS promise for individual developers and small teams.

The five streams, ordered by activation effort (low → high):

| # | Stream | Activation effort | Target ARR/customer |
|---|--------|-------------------|---------------------|
| 1 | Hosted Sidecar SaaS (`sidecar.crprotocol.io`) | Medium (4–6 weeks) | $99 → $999 / month |
| 2 | Commercial source licence (`CRP_LICENSE_KEY`) | Low (2 weeks) | $499 → $75,000 / yr |
| 3 | Watermark-removal soft-gate (community → pro) | Low (1 week) | $99 / yr |
| 4 | Usage-cap freemium (local rolling counter) | Low (1 week) | conversion driver |
| 5 | Managed-service / support contracts | Medium (sales-led) | $25k+ / yr |

## 2. Stream 1 — Hosted Sidecar SaaS

### Product

A single-container, OpenAI-compatible HTTP gateway that speaks CRP
internally:

```
docker run -p 8900:8900 \
  -e CRP_LICENSE_KEY=... \
  crprotocol/sidecar:latest
```

The user points their existing OpenAI client (`base_url=http://localhost:8900/v1`)
at the sidecar. The sidecar:

1. Routes between any combination of OpenAI / Anthropic / Groq /
   local Ollama / LM Studio according to the CRP routing manifest.
2. Maintains the **shared Continuity-Knowledge Frame (CKF)** so a
   conversation can hand off between models without re-priming.
3. Caches CRP frames so identical prompts across models cost ~60%
   less in token spend.
4. Emits a structured audit log for every dispatch (`POST
   /sessions/:id/dispatch`).

### Pricing

| Plan | Price | Sessions / mo | Models | Audit retention | Support |
|------|-------|---------------|--------|-----------------|---------|
| Community | $0 | 100 | 2 (OpenAI + 1 local) | 7 days | GitHub issues |
| Pro | $99 / mo | 5,000 | unlimited | 30 days | email, 48h SLA |
| Enterprise | $999 / mo | 100,000 | unlimited + private deployment | 1 year | dedicated Slack, 8h SLA |

Overage on Pro: $0.02 / session above 5k. Overage on Enterprise:
custom contract.

### Activation steps

1. **Domain**: stand up `sidecar.crprotocol.io` (or
   `crprotocol.io/sidecar` for cost). Marketing page first; product
   second. (See Section 7 — landing-page spec.)
2. **Container image**: tag `crprotocol/sidecar:0.1.0` on Docker Hub
   from the existing protocol reference impl + an OpenAI-compat shim.
3. **Billing**: reuse the `crp-comply` Stripe integration (already
   shipped). New product IDs: `prod_sidecar_pro`, `prod_sidecar_ent`.
4. **License-key issuance**: same flow as `crp-comply` enterprise keys
   (admin-only POST `/licenses` → emits a signed JWT with
   `aud=sidecar`, `sub=customer_id`, `tier`, `exp`, `quota`).
5. **Telemetry**: anonymised session-count beacon back to a Cloudflare
   Worker; if license is invalid or missing, fall back to Community
   limits and watermark.
6. **Day-1 launch artefacts**: README badges, Hacker News post, a
   short Loom showing "swap GPT-4 for Llama 3 mid-conversation
   without context loss".

## 3. Stream 2 — Commercial source licence (`CRP_LICENSE_KEY`)

### Why dual-licence

The protocol stays MIT-permissive for individuals and OSS use. The
**reference server implementation** moves to a source-available
licence (BSL-1.1 with a 4-year-to-Apache transition is the
recommended template) that requires a commercial key when used by
**organisations with > $1M ARR or > 50 employees**.

Verification is honour-based plus a startup banner:

```
[CRP] No commercial licence detected. If you operate at >$1M ARR
[CRP] or >50 employees, see https://crprotocol.io/license.
[CRP] Free for OSS, evaluation, and small teams.
```

### Tiers

| Tier | Price (annual) | Includes |
|------|----------------|----------|
| Startup | $499 | <= 25 seats, email support |
| Growth | $5,000 | <= 250 seats, audit-log export, 99.5% uptime advisory |
| Enterprise | $25,000 | unlimited seats, on-prem build artefacts, signed SBOM |
| Strategic | $75,000 | private fork, named SRE escalation, custom routing plugins |

### Activation steps

1. Replace `LICENSE` in protocol repo with `LICENSE-BSL.md` +
   `LICENSE-OSS.md` (dual). Add a `COMMERCIAL.md` explaining who
   needs a key.
2. Add a `validate_license_key(env)` function to the reference
   server. Soft-fail (warning only) for now — hard-fail is reserved
   for v2.
3. Stripe checkout link generator at `crprotocol.io/license`. Issue
   keys via the same JWT minter as the sidecar.
4. Notify existing pilot customers 30 days before BSL transition.

## 4. Stream 3 — Watermark-removal soft-gate

The reference server appends `X-CRP-Watermark: community` to every
response and includes a single line in the boot banner:

```
Powered by Context-Relay-Protocol (community edition)
```

A valid `CRP_LICENSE_KEY` of any paid tier removes both. This is
**deliberately gentle** — it converts ~2–4% of users without
alienating OSS adopters.

### Activation
Single PR. Ships in protocol reference server v0.4.

---

## 5. Stream 4 — Usage-cap freemium (local rolling counter)

The reference server keeps a rolling 30-day counter in
`~/.crp/usage.jsonl`:

```jsonc
{"day": "2025-11-12", "sessions": 47, "frames": 312}
```

When the rolling sum crosses `1,000 sessions / 30 days` and no
license key is present, the server returns HTTP 429 with a friendly
message linking to the upgrade page. **No phone-home** — counter is
purely local. A determined user can `rm ~/.crp/usage.jsonl`; that's
fine, the gate is a conversion nudge, not DRM.

### Activation
Single PR alongside the watermark soft-gate.

## 6. Stream 5 — Managed service & support

The same sales motion that works for `crp-comply` enterprise:

- **Implementation engagement**: $25k flat fee, 4-week deployment
  with the customer's data team. Includes routing-manifest tuning
  for their model mix.
- **Annual support**: 20% of the licence tier price, includes
  named contact + monthly review calls.
- **Custom routing plugins**: T&M, $250/hr, capped per-engagement.

This stream is sales-led and does not require new product work.
Activate when Stream 1 hits 10 paying Pro customers (signal: there
is enough non-trivial deployment surface to warrant paid services).

### Hero

> **OpenAI-compatible. One container. Every LLM. 60% cheaper context.**
>

> a shared memory across models, deterministic context replay, and a
> single audit trail — without rewriting a line of code.
>
> `docker run -p 8900:8900 crprotocol/sidecar`
>

### Three-up "why"

1. **Cost**: deduplicated context frames cut token spend ~60% on
   multi-model workflows (benchmark link).
2. **Portability**: switch between GPT-4, Claude, Llama 3 mid-session
   without re-priming. Your code only knows OpenAI.
3. **Memory**: the Continuity-Knowledge Frame (CKF) persists across
   models, restarts, and sessions. Bring your own storage backend.

  -H "Authorization: Bearer sk-anything" \
  -d '{

  }'

## 9. Risks

- **OSS backlash on dual-licence**: mitigated by keeping the protocol
  itself MIT and only relicensing the reference *server*. Document
  this distinction prominently.
- **Sidecar latency tax**: shim must add < 5 ms p99. Benchmarks are
  the marketing surface; bad benchmarks kill the product.
- **Licence-key piracy**: keys are JWTs signed with our private key.
  Revocation is via a short-TTL CRL endpoint the sidecar fetches
  daily. Acceptable for honour-based commercial use; not DRM.
