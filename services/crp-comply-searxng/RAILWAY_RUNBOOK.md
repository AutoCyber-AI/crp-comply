# Railway runbook — fixing your deployment

## TL;DR — what's wrong and what to do

| Symptom | Cause | Action |
|---|---|---|
| `crp-comply-searxng` build fails: *"docker VOLUME at Line 31 is not supported"* | Railway forbids `VOLUME` in Dockerfiles | Already fixed in this commit. Push and redeploy. |
| Two services exist (`searxng` and `crp-comply-searxng`) | The `searxng` service was created from the old standalone template, before we built our overlay | **Delete the `searxng` service**. Keep only `crp-comply-searxng`. |
| Private DNS is `radiant-achievement.railway.internal` | Railway autogenerated the subdomain | Rename the DNS to `crp-comply-searxng` so it matches `CRP_COMPLY_SEARXNG_URL` |
| Redis added but not connected | Variable not set on the searxng service | Set `SEARXNG_REDIS_URL = ${{Redis.REDIS_URL}}` (Railway template ref) |
| Volume size 5 GB | Default | Fine — leaves room for years of feedback DB growth |

## Step-by-step

### 1. Delete the standalone `searxng` service

Railway dashboard → project → `searxng` service → **Settings** → scroll to bottom → **Danger** → **Delete service**.

Why: we don't need the upstream-template service anymore. All SearXNG behaviour is now defined by `crp-comply-searxng`, which builds from our `crp-comply` repo with our overlay configs and intelligent agent plugins. Two services would only fight over routing.

### 2. Rename the private DNS on `crp-comply-searxng`

Dashboard → `crp-comply-searxng` → **Settings** → **Networking** → **Private Networking** → DNS field → change `radiant-achievement` → `crp-comply-searxng` → **Update**.

Final result must read: `crp-comply-searxng.railway.internal`. This is the URL `CRP_COMPLY_SEARXNG_URL` already points at on the main service.

### 3. Push the Dockerfile fix

```bash
git pull --rebase
git push origin master
```

Railway will redeploy `crp-comply-searxng` automatically. Watch the build logs — the `VOLUME` line is gone; the new line is a `mkdir -p /var/lib/searxng-crp` so the directory exists for the SQLite path even if no Railway Volume is attached yet.

### 4. Set Railway env vars on `crp-comply-searxng`

Dashboard → `crp-comply-searxng` → **Variables** tab. Add (or update):

| Variable | Value | Source |
|---|---|---|
| `SEARXNG_SECRET_KEY` | 64-hex random string | run `openssl rand -hex 32` locally and paste |
| `SEARXNG_REDIS_URL` | `${{Redis.REDIS_URL}}` | Railway template ref — Variables tab → "Add Reference" → pick the Redis service |
| `SEARXNG_SETTINGS_PATH` | `/etc/searxng/settings.yml` | already in our Dockerfile, but harmless to pin |
| `INSTANCE_NAME` | `crp-comply-searxng` | display only |
| `PORT` | leave **unset** | our settings.yml hard-codes `8080` |
| `BASE_URL` | leave **unset** or empty | service is internal-only; no public URL |

Delete any other variables left over from the deleted `searxng` template (`UWSGI_*`, `SEARXNG_SECRET` (singular)).

### 5. Confirm the volume

Dashboard → `crp-comply-searxng` → **Volumes** tab → confirm one volume mounted at `/var/lib/searxng-crp`. 5 GB is fine. If the mount path is different, edit it.

### 6. Verify env vars on `crp-comply-search` (the existing service)

Dashboard → `crp-comply-search` → **Variables**. Confirm:

| Variable | Value |
|---|---|
| `CRP_COMPLY_WEBSEARCH_BACKEND` | `searxng` |
| `CRP_COMPLY_SEARCH_BACKEND` | `searxng` (same value — the sidecar reads this name internally) |
| `CRP_COMPLY_SEARXNG_URL` | `http://crp-comply-searxng.railway.internal:8080` |
| `CRP_COMPLY_SEARXNG_ENGINES` | leave **unset** or empty — the host-side router selects engines per intent |
| `CRP_COMPLY_SEARCH_API_KEY` | a strong random token (used by main API to call this sidecar) |

> Why two var names? `CRP_COMPLY_WEBSEARCH_BACKEND` was the original name in PHASE_7 §16.2. `CRP_COMPLY_SEARCH_BACKEND` is what the sidecar's `AppConfig.from_env()` actually reads. Set both to `searxng` to be safe.

### 7. Smoke-test from Railway

Open a **shell** in `crp-comply-search` (Deployments → ⋯ → Shell). Run:

```bash
curl -sf http://crp-comply-searxng.railway.internal:8080/healthz \
  && echo "✓ SearXNG up"

curl -s 'http://crp-comply-searxng.railway.internal:8080/search?q=GDPR+article+5&format=json&crp_intent=regulation_text' \
  | jq '.results[0] | {url, engine}'
# Expect: an eur-lex.europa.eu URL surfacing near the top because the
# router plugin promoted the eur_lex engine for regulation_text intent.

curl -s http://crp-comply-searxng.railway.internal:8080/crp/scores/regulation_text | jq .
# Expect: {"intent":"regulation_text","scores":{}} initially — the
# learning reranker has no observations yet. After a few real agent
# runs feed it via POST /crp/feedback, scores populate.
```

### 8. Connect Redis (one-time)

If you provisioned Redis but haven't wired it: dashboard → `crp-comply-searxng` → Variables → **+ New Variable** → **Add Reference** → pick `Redis.REDIS_URL` → name it `SEARXNG_REDIS_URL`. Save → service auto-redeploys with Redis cache enabled (response cache for SearXNG itself, not our learning DB).

If you don't want Redis right now, you can delete the Redis service or leave it disconnected; SearXNG falls back to in-process cache (less efficient but functional). Our settings.yml uses `!env SEARXNG_REDIS_URL` so an unset/empty value just means no Redis backend.

## After redeploy

You should see two services in the project:

```
crp-comply             (main FastAPI)
crp-comply-search      (intelligence sidecar, agent #1)
crp-comply-searxng     (host-side intelligent SearXNG, agent #2)  ← NEW
Redis                  (optional cache for SearXNG)
```

DNS map (private, internal-only):

```
crp-comply-search.railway.internal:8081  →  reachable from main API only
crp-comply-searxng.railway.internal:8080 →  reachable from crp-comply-search only
```

## Common follow-up errors

| Error | Cause | Fix |
|---|---|---|
| `502 Bad Gateway` from `/healthz` | service still booting | wait 60s after redeploy |
| `connection refused` from `crp-comply-search` | DNS rename not picked up | redeploy `crp-comply-search` after step 2 |
| `KeyError: SEARXNG_SECRET_KEY` in logs | step 4 not done | set the var, redeploy |
| `sqlite3.OperationalError: unable to open database file` | volume not mounted | step 5 |
| Engine `eur_lex` returning nothing | EUR-Lex changed its HTML | log issue; the four custom engines parse HTML so they need maintenance from time to time |
